## Operating rules (these override any local preference)

1. **Iterate continuously.** Work Phase 3.2 → 3.3 → Wave 4 → 5 → 6 → 7 without
   stopping to ask permission. Stop only for (a) a genuinely ambiguous
   requirement that cannot be resolved from the analysis document, or (b) a
   critical blocker — a missing runtime, a frozen digest moving inexplicably, a
   gate that cannot go green without breaking a hard rule. Where the plan says
   **RESOLVE FROM REPO**, resolve it by reading, not by asking.
2. **Pre-flight before every phase.** Run the plan's pre-flight checklist for
   that phase and fix everything you find. If the problem is one the plan
   explicitly defers to a later phase, **document it and move on** — do not
   fix early.
3. **Adversarial `@heavy` QA after every phase. Always.** QA is a heavy-tier
   task without exception, even where a plan heading says "`@medium`
   checklist" — that heading is the minimum, not the ceiling. Fix **every**
   finding. BLOCKER/MAJOR gets a `fix(<scope>)` commit plus a targeted
   re-review that reads only the fix; MINOR gets fixed without re-review.
   "Zero open findings" means zero open BLOCKER/MAJOR **and** every MINOR
   fixed.
4. **Delegate through the model router, always, preferring atomic tasks.**
   `@fast` for read-only gathering, `@medium` for mechanical implementation,
   `@heavy` for complex coding, mechanism-seam design and every QA review.
5. **Split the heavy lift from the post-work.** Gather context with `@fast`,
   design and write the hard code with `@heavy`, then run and collect tests
   with `@fast`/`@medium`. Never ask `@heavy` to run a suite and report.
6. **When the router blocks you, take over personally.** You are a top-tier
   model. If a weaker agent returns prolix non-work, or the acceptance gate
   rejects a substantively correct result on a process technicality, verify by
   hand and do the read or the edit yourself. Never re-dispatch the same prompt
   a third time. See "Router misfires" below for the exact known failure modes.
7. **Never run the full suite when you do not need it.** During iteration run
   only the files your change touches. Run `GATE-COMMIT` once immediately
   before each commit and `GATE-WAVE` at each wave end.
8. **Parallelise aggressively.** Issue independent read-only dispatches in one
   message. Run independent vitest invocations concurrently. Never run two
   _writing_ tasks against the same worktree.
9. **Commit often.** One Conventional Commit per concern, always
   `git commit -s`, always explicit absolute paths in `git add`, never
   `git add -A`, never `--amend`. Fix forward. Gate before committing.
10. Always use full absolute paths everywhere.

### Gate vocabulary

- `GATE-COMMIT` = `npm run lint && npm run typecheck && npm test && npm run build && npm run format:check`
- `GATE-WAVE` = `GATE-COMMIT` then `npm run test:coverage && npm run pack:check && npm run test:pack && npm run fixtures:check`

## What Phase 3.2 has to do, and what makes it dangerous

Phase 3.2 adds four registry-driven push sites plus the `ComposeBetasInput`
thinking-signal extension (commit C8). Phase 3.3 adds the fifth site, the
`redact_thinking` removal and the body field (commit C9). **They are one seam;
a single combined `@heavy` QA runs at the end of 3.3.** C8 and C9 stay two
separate commits.

Start with **Task 3.2.1**, the `@heavy` design note. It fixes the whole
mechanism seam in one place: the input field, the call order and its
key-insertion-order invariant, the `ComposedBetas` override field, the
`injectThinkingDisplayUpdates` predicate and its provider condition, the
clear-at key spelling, the inert-audit shape, and the `suppressBetas`
semantics. Deciding any of those twice is how the two halves drift apart. The
note is carried into Tasks 3.2.2 and 3.3.2 and into `MEMORY.md` at Phase 6.1.

### The four hazards, in order of how quietly they fail

1. **The clear-at registry key spelling.** `ComposableBetaRegistry`'s new key
   must match what `src/profiles/beta-registry-2.1.280.ts` actually declares,
   character for character. Convention is the uppercased featureKey, so
   `MID_CONVERSATION_SYSTEM_CLEAR_AT` — but the plan sometimes writes
   `MID_CONV_SYSTEM_CLEAR_AT`. **The registry file is authoritative.** A
   mismatch makes the site silently inert and only the fourteen-identifier
   literal test in Phase 3.3 catches it.
2. **All five new keys must be optional** (`KEY?: BetaRegistryEntry`),
   following the existing `NARRATION_SUMMARIES?` precedent. The 2.1.195
   registry (28 keys) and the 2.1.233 registry (31) lack them; making them
   required breaks compilation and moves both frozen digests.
3. **"Fired in this composition" means the site pushed in this call** — track
   it with a local boolean set at site 11. It does **not** mean "the registry
   has the key".
4. **One negative test per guard conjunct per site.** Without them, an
   implementation that silently drops the `experimental` conjunct passes every
   other test in the plan, including the fourteen-identifier literal.

### Facts already established that Phase 3.2 depends on

- `ComposableBetaRegistry` (`src/betas.ts:54-72`) currently declares **sixteen
  required keys plus exactly one optional**, `NARRATION_SUMMARIES?`. The nine
  2.1.280-only keys are absent from the type entirely, so `composeBetas` has no
  push site for any of them yet.
- `ComposedBetas` (`src/betas.ts:129-132`) is

- The packed-consumer digest hashes `{url, method, headers, body}` only —

- `resolveBetaRegistry` is now **exported** from `src/betas.ts` for deep import

## Tooling traps

- **There is no `npm run format`.** Use `npx prettier --write <absolute paths>`.
  `docs/protocol/` is prettier-ignored; `docs/plans/` and `docs/source-trace.md`
  are **not**.
- vitest 4 removed `--reporter=basic`. Use `--reporter=dot`.
- ESLint bans `ReadonlyArray<T>` (use `readonly T[]`), the two-argument
  `expect(value, message)` form, and `toThrowError` (use `toThrow`). Put the
  diagnostic inside the asserted value.
- `exactOptionalPropertyTypes` is on: build optional fields with conditional
  spreads, never `field: maybeUndefined`. An absent key and a key holding
  `undefined` are different bytes on the wire.
- Never suppress a type error (`as any`, `@ts-ignore`, `@ts-expect-error`).
  That last one is also why type-level non-assignability assertions use vitest
  `expectTypeOf`.
- **Type-level assertions must live in `test/types/`.** `npm run typecheck` is
  `tsc -p tsconfig.json --noEmit && tsc -p tsconfig.types.json --noEmit`;
  `tsconfig.json` excludes `test` entirely and `tsconfig.types.json` includes
  only `src/**` plus `test/types/**`. `vitest.config.ts` declares no
  `typecheck` block. So nothing under `test/` except `test/types/` is
  typechecked, and an `expectTypeOf` in `test/validation/` proves nothing.
  **Prove each new type-level assertion non-vacuous** by temporarily inverting
  it and observing `tsc` fail — this caught a real gap in Phase 3.1.
- `tsconfig.eslint.json` carries `allowJs: true` and includes
  `scripts/lib/**/*.mjs` so the shared pack parser lints. A `.d.mts` sidecar
  does **not** work: it matches neither ESLint glob, inherits `strictTypeChecked`
  with no parser project, and crashes `eslint .` with exit 2.
- `npm run fixtures:seal` refuses when any tracked file outside its two targets
  is modified, when any untracked file sits inside the golden directory, or when
  `CI` is truthy. Clear it for that invocation only:
  `Remove-Item Env:CI -ErrorAction SilentlyContinue; npm run fixtures:seal`.
- `manifest.models` in the golden manifest is hand-maintained seal _input_ —
  edit it by hand or the generated table renders `n/a`.
- On Windows `Get-FileHash -Algorithm SHA256` matches the raw-byte hashing the
  tests use; the seal script detects and preserves per-file EOL.

## Router misfires, and what to do about them

These are the exact failure modes observed this cycle. When one occurs, take
over and do the work yourself.

- **`Task(subagent_type="medium")` refusing to act.** Given a structured
  seven-section prompt with an `[acceptance]` block it replied four times in a
  row that "the Task tool is not available in this session and sub-delegation
  is prohibited". The workaround is plain-language framing — "You are editing
  ONE file yourself, using Read and Edit. There is nothing to delegate." — plus
  simple `--- EDIT n ---` blocks. `subagent_type="general"` never exhibited it.
- **Delegates ending a dispatch with "hand this to a medium subagent".** Every
  tier below the orchestrator lacks a Task tool. They correctly do the work
  themselves; expect the note and ignore it.
- **`@fast` reporting "DONE … read verbatim above" without pasting anything.**
  The subagent's tool output is invisible to you — only its final message
  arrives. For "read a file and report it verbatim" dispatches, either demand
  the content inline in the final message or read the file yourself. This
  happened on the first Phase 1.1 dispatch and cost a full round trip.
- **The acceptance gate rejecting substantively correct work** on process
  technicalities: no tool trace proving Read/Edit rather than Write; a command
  not on the allowlist (`node -e`, `echo ok`); an expected substring absent
  from the report text. Verify by hand and accept.
- **Read-budget caps.** Baselines are `@fast` 8, `@medium` 5, `@heavy` 3.
  Override with `CAP:N`, or `CAP:none` **plus** a `reason:` line in the same
  dispatch — an unjustified `CAP:none` silently falls back to the baseline and
  the delegate gets halted mid-task. A delegate that goes over budget for a
  good reason (finishing an edit that would otherwise leave lint broken) made
  the right call.
- **Never re-dispatch the same prompt a third time.**

## Substantive lessons from Waves 0–3 — carry these forward

- **A count in prose beside the literal that states it is the staleness class
  this repository keeps rediscovering.** "Two pinned profiles", "nine
  capabilities", "the six catalogue-backed fields", "a tenth mandatory key",
  "three lines away" — every one of them went stale during this port and every
  one was caught by QA rather than by a test. When you write a comment, point
  at the literal instead of restating it.
- **An adversarial reviewer's MAJOR is a hypothesis, not a verdict.** One
  review claimed `family` reaches the wire, citing real forwarding sites. It
  does not: the only sink is `RedactedRequestEvidence.modelFamily`, returned as
  a _sibling_ of `body`/`headers` and never merged into either. Trace the sink
  before accepting a finding — and before rejecting one.
- **Grepping for a type name finds declarations, not exact-match assertions.**
  Phase 3.1's inventory of `ClaudeCodeCapabilities` construction sites missed
  `test/models.test.ts`, where `it.each` rows are destructured and then
  _reassembled_ into a literal passed to `toEqual`. It also missed two key
  _lists_ in `src/build-request.ts` (`CAPABILITY_KEYS`,
  `parseCapabilityDecisions`) that a type-name grep cannot see. Only the full
  suite found them.
- **`evidence.capabilityDecisions` records what the caller _requested_, not
  what the model supports** — every field is `requested?.field ?? false`. A
  request with no `capabilities` key yields an all-`false` row for any model.
- **`parseBuiltClaudeCodeRequest` defaults its profile argument to
  `DEFAULT_PROFILE`.** Pass the profile explicitly when round-tripping a
  non-default build, or it fails with `INVALID_INPUT`.
- **Two recurring test failures were diagnosed, not papered over.**
  `vitest.config.ts` sets no `testTimeout`, so everything inherits the 5,000 ms
  default; `test/property/request-invariants.test.ts` (60 generated cases, each
  hashing) and both `npm pack` subprocess cases in
  `test/pack/pack-policy.test.ts` cross it under CPU contention. They now carry
  explicit `30_000` timeouts with the derivation written down, and both
  `execFileSync` calls carry `timeout: 30_000`. Reproduced deterministically by
  running competing suites; green afterwards under the same contention. Do not
  raise the global timeout.
- **`main` is red on `test:coverage` until this port merges**, because the
  pre-landed `beta-registry-2.1.280.ts` draft was imported by nothing. Phase
  1.1 closed it on this branch (`functions` back to 100%). Do not cut a release
  before the merge.
- **Two unplanned Wave 0 repairs** are in the history and worth knowing about:
  npm 12 changed `npm pack --json` from an array to an object keyed by package
  name (both shapes are now accepted in one shared parser,
  `scripts/lib/pack-json.mjs`), and the frozen digests were never actually
  asserted by anything — the gate only checked cross-runtime agreement.
